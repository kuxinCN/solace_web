# Solace

> 给每一个不想说话的灵魂，一点慰藉。

一个**情绪陪伴**应用：用户可以找人说话、写日记、用情绪急救工具缓一缓。

**产品边界（很重要）**：
- 它不是心理咨询、不是治疗，**不做任何诊断**；
- AI 的角色是**倾听和陪伴** —— 不讲道理、不给人生建议、不评判对错、不催人振作；
- 界面和交互上刻意回避"打分""评级""进步/退步"这类表达（详见「日记情绪标签」一节）。

**重装只重置管理员账号，用户、聊天、日记等业务数据不受影响。**

## AI 能力配置

### 对话 AI

后台「对话 AI」页面，填**接口地址 + API Key + 模型名**即可，必须兼容 **OpenAI 协议**：

| 服务商 | 接口地址示例 |
|---|---|
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |
| DeepSeek | `https://api.deepseek.com/v1` |
| OpenAI | `https://api.openai.com/v1` |
| 小米 MiMo | `https://api.xiaomimimo.com/v1` |

> 接口地址**填到版本目录、或直接粘官方文档给的完整地址（`…/v1/chat/completions`）都可以**，程序会自动识别，不会重复拼接。

### 语音 TTS

后台「语音 TTS」页面先选**接口类型**，两种协议的请求方式不同：

| 接口类型 | 端点 | 认证头 | 音频返回位置 |
|---|---|---|---|
| **OpenAI 兼容** | `{接口地址}/audio/speech` | `Authorization: Bearer` | 响应体（二进制） |
| **小米 MiMo** | `{接口地址}/chat/completions` | `api-key` | `choices[0].message.audio.data`（base64） |

小米 MiMo 参考配置：地址 `https://api.xiaomimimo.com/v1`、模型 `mimo-v2.5-tts`、音色 `mimo_default`、格式 `mp3`。
（注意 Key 前缀要与地址对应：`sk-` 配 `api.xiaomimimo.com`，`tp-` 配 `token-plan-cn.xiaomimimo.com`）

### 提示词（AI 人设）

**提示词存在数据库里，后台改完保存立即生效，不用重启也不用重新构建。**

- 「AI 提示词（人设）」：角色设定与说话风格。留空则回退到前端自带的提示词
- 「读日记时的附加提示词」：用户写完日记后追加给 AI 的指令，用 `{diary}` 表示日记正文位置

> 这是答辩/演示很好用的功能：现场改一句提示词，用户端回复风格立刻变化。

### 日记：情绪标签 + AI 生成

**① 情绪标签**

AI 会给每篇日记打一个情绪标签，用于让用户感到"被看见"。**它只有 8 个温和的描述词**：

```
轻快 · 平静 · 安稳 · 有点沉 · 疲惫 · 烦躁 · 孤单 · 说不清
```

**② AI 生成日记**（可选，默认关闭）

每天定时读当天的聊天记录，替用户写一篇日记。生成结果里**同时带出标签**（一次调用搞定，不用再打一遍标），并写入两个关键字段：

- `source = 'ai'` → 前端标上「**AI 生成 · 09/22**」
- `diary_date` = **聊天那一天**（不是生成时刻 —— 23 点写的是"昨天"的事）

**设计约定（改动前请先读）**：

| 约定 | 原因 |
|---|---|
| 用词表白名单，模型从 8 个词里选 | 防止 AI 写出"抑郁倾向明显"这类诊断性词汇 |
| **不做数值评分** | 没有"62 分"，不给情绪排名 |
| **不做趋势对比** | 不出现"你比上周更糟了" |
| 日记**不审核**、也不进内容审核队列 | 日记是私人空间，不是"别人能看到的内容" |
| AI 生成的必须**明确标注** | 用户得知道不是自己写的，否则会以为账号被盗 |
| 拿不准就输出「说不清」 | 允许说不清，不逼着给答案 |

> ⚠️ 原来的约定里有一条「标签只呈现，不触发自动建议」。
> 现在"要不要放松"这类**主动询问**由「压力评估」模块负责，规则更严：
> 只在**连续两次**超过阈值时才会问，有冷却、可关闭，且用户点一次「先不用」就自动把阈值 +5。
> **日记的标签本身仍然只呈现、不弹任何东西。**

**打标和生成都走批量推理**，批次名在小米控制台里各自成行：`Solace·日记打标` / `Solace·日记生成`。

接口：`POST /api/user/diaries`（保存时自动入队）、`GET/PATCH /api/user/diaries`

### 内容审核（异步 · 批量推理）

**只审"别人能看到、且是用户自己填的内容"** —— 昵称 / 签名 / 头像 / AI 头像 / 聊天背景 / 我的页背景。聊天消息由 `content-guard` 实时拦，日记不审。

流程：用户改资料 → **立刻生效** + 打「未审核」标记 + 进队列 → 批量提交给小米 → 轮询回收 → 合规就清标记，违规就回填默认值。

**几个关键约定（都踩过坑）**：

| 约定 | 原因 |
|---|---|
| **四个调用全走批量地址**（上传 / 创建 / 查状态 / 下载） | 少一个就会一直显示"进行中" |
| 创建批次必须带 `name` 字段 | ⚠️ **官方文档没写，但不传直接 500** |
| 解析不出结论 → 标 `failed` 交人工 | 宁可让人看一眼，也不默认放行 |
| 图片不进批量，走人工或逐条 | 多模态消息体会让整批创建失败 |
| 按任务类型**拆批次** | 控制台里审核 / 打标 / 生成各自成行，好排查 |

详见 [docs/CONTENT-REVIEW.md](./docs/CONTENT-REVIEW.md)。

### 压力评估与放松提醒（实时 · 可选）

**⚠️ 默认关闭**，在后台「内容安全与压力」里打开。

四层漏斗 —— **九成以上的消息不花任何 Token**：

```
① 本地词表打分（每条消息，0 Token，<20ms）
② EMA 平滑 + 聊天 / 日记双通道融合
③ 触发判断：每 10 条 · 命中关键词（2 分钟冷却）· 危机词
④ 只有触发时才调一次 AI 深度识别（只取最近 3 条，输出 30 token 的极简 JSON）
```

**⚠️ 它和内容审核是两条完全不同的路**：

| | 内容审核 / 日记打标 | 压力评估 |
|---|---|---|
| 时机 | **异步**，提交后等几分钟 | **实时**，发完消息就要判断 |
| 接口 | 小米**批量推理**（五折价） | **对话接口**（批量来不及） |
| 目的 | 合规 / 归档 | 及时接住用户 |

**设计红线（改动前请先读）**：

| 约定 | 原因 |
|---|---|
| ⚠️ **不诊断** | 界面上出现的是"情绪档位"（「有点累」），不是"你有焦虑倾向" |
| ⚠️ **危机词一票通行** | 跳过阈值、冷却、开关，直接弹干预 + 热线 |
| 危机词用**带上下文的正则**，不用 `includes()` | 中文没有词边界：「焦虑**消失**了」会被误判成危机 |
| 情绪档位的措辞**后台可配** | 语气要贴产品调性，不能写死在代码里 |
| 用户点「先不用」→ **阈值真的 +5** | 拒绝不能只是视觉上消失，系统要真的变得更含蓄 |
| 压力值**不给后台看个体** | 这数据比聊天记录还敏感 |

详见 [docs/STRESS-DESIGN.md](./docs/STRESS-DESIGN.md)（含与原始规格的 5 处修订对照）。

## 安全设计

| 项 | 做法 |
|---|---|
| **会话** | 数据库只存 `sha256(token)`，即使被拖库也无法直接登录；Cookie 为 HttpOnly |
| **管理员密码** | bcrypt 哈希，不可逆 |
| **管理员登录** | 密码 + TOTP 动态验证码双因素；连续 5 次失败锁定 10 分钟 |
| **用户密码** | AES-256-GCM 可逆加密（业务要求后台可查看，安全权衡见 DEPLOY.md 附录） |
| **SQL 注入** | 全部使用预处理语句；动态列名走白名单映射 |
| **XSS** | 邮件模板与日志输出统一做 HTML 转义；前端不用 `dangerouslySetInnerHTML` |
| **限流** | 发码、校验码、登录、上传、改密、改邮箱、AI 调用、安装入口均有独立限流 |
| **错误信息** | 默认脱敏，MySQL 原始报错只写服务端日志，不返回给前端 |
| **上传校验** | kind 白名单 → data URL 前缀 → **文件头魔数比对真实格式** → 格式一致性 |
| **审计** | 登录、改配置、查看明文密码等敏感操作全部写 `audit_logs` |
| **备份脚本** | 数据库密码走临时配置文件，不出现在进程列表里 |

| **日志轮转** | `pm2 install pm2-logrotate`（防止日志撑爆磁盘） |
| **压测** | `scripts/bench.sh` —— 输出 QPS / P50 / P95 / P99 |
| **慢查询/巡检** | 见 [docs/OPERATIONS.md](./docs/OPERATIONS.md) 的巡检清单与故障速查表 |

## 常见问题

**Q：页面报 `Internal Server Error`（整页只有这一句话）？**
A：多半是 `.next` 构建产物不完整。执行：

```bash
cd /项目目录
pm2 stop solace
rm -rf .next
npm run build        # 必须看到 ✓ Compiled successfully
pm2 start solace
```

**Q：域名 502 / 500，但 `127.0.0.1:3000` 正常？**
A：检查是否有**两个实例**在跑（宝塔 Node 项目 + pm2），以及 Nginx 的 `proxy_pass` 端口是否指向正在跑的那个：

```bash
ss -lntp | grep -E ':3000|:3001'
grep proxy_pass /www/server/panel/vhost/nginx/*.conf
```

**Q：构建报 `Build failed because of webpack errors`？**
A：真正原因在上面几行，跑这个直接看：

```bash
npm run build 2>&1 | grep -A4 "Can't resolve"
```

**Q：所有请求都卡住然后 500？**
A：先看数据库活着没：`systemctl status mysqld`，再 `curl -s http://127.0.0.1:3000/api/health`。

**Q：后台登录提示"账号已锁定"？**
A：连续错 5 次会锁 10 分钟，清掉即可：

```sql
UPDATE admin_users SET failed_attempts = 0, locked_until = NULL;
```

**Q：改完代码页面没变化？**
A：`npm run build` 之后**必须重启进程**（`pm2 restart solace`）；浏览器侧用无痕窗口或 `Ctrl + F5`。

**Q：TTS 试听报 400 / Invalid request？**
A：检查「接口类型」是否选对（OpenAI 兼容 vs 小米 MiMo 的请求方式完全不同），以及模型名、音色名是否拼对。
