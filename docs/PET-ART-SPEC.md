## 1. 一句话需求

> 画一只**会在网页右下角安静待着的小生物**。它**不卖萌讨好、不催人、不会难过**。
> 它需要的不是"可爱"，是**"可靠地在那里"**。

### 它要传达的感觉

| 要 ✅ | 不要 ❌ |
|---|---|
| 安静、温和、有点钝 | 活泼、兴奋、抢眼 |
| 像一个"陪着你但不多话的朋友" | 像一个"求你陪它玩的宠物" |
| **低饱和、柔和的颜色** | 高饱和、荧光色 |
| 简单的形体，一眼看得懂 | 复杂的细节堆砌 |

---

## 2. 造型要求

### 2.1 完全自由的部分

- **物种**：不用是现实存在的动物。可以是抽象小生物、云朵精灵、圆乎乎的团子、机械小方块……**你们自己定**
- **风格**：扁平 / 半厚涂 / 描边 / 无线稿，都可以
- **细节**：可以有角、有触角、有光晕、有飘带

### 2.2 必须满足的硬约束

| 约束 | 为什么 |
|---|---|
| **① 轮廓清晰** | 显示尺寸只有 **64-96px**，细节会糊成一团。**剪影就能认出来**才算合格 |
| **② 能拆分部件** | 见第 5 章。**眼睛和尾巴必须是独立的图层**，否则动不起来 |
| **③ 有"眼睛"这个可辨认的特征** | 眨眼是让它"活着"最有效的手段 |
| **④ 正脸或 3/4 侧脸** | 要能面对用户 |
| **⑤ 建议朝向偏左** | 放右下角时，视线朝向页面内容，不背对用户 |
| **⑥ 重心稳** | 静止时看起来是"稳稳待着"，不是"快要倒了" |

### 2.3 关于显示尺寸

它在页面上**实际显示只有 64-96 像素宽**。

**判断标准**：把你的设计稿缩到 80px 宽，**如果还能看出"这是一个有眼睛的小生物"**，就合格了。

测试方法：把图缩到 80px，眯起眼睛看 —— 认不出来的话，就是细节太多了。

## 3. 画布与坐标系

### 3.1 基本设置

| 项 | 值 |
|---|---|
| **画布尺寸** | **512 × 512 像素**（正方形） |
| **背景** | **完全透明** |
| **颜色模式** | RGB（不要 CMYK） |
| **原点** | 左上角 (0, 0) |
| **中心点** | (256, 256) |

### 3.2 安全边（重要）

**四周各留 40px 的空白，不要有任何内容。**

```
┌──────────────────────────────────────────────┐
│ ⬅ 40px                                      │
│   ┌──────────────────────────────────────┐   │
│   │                                      │   │  ⬆
│   │        有效绘制区域                  │   │  40px
│   │        432 × 432                     │   │
│   │                                      │   │  ⬇
│   └──────────────────────────────────────┘   │
│                                             │
└──────────────────────────────────────────────┘
```

**为什么**：动画会让它**放大 3%、上移 3px、旋转 8°**。如果内容顶到边缘，一动就会被裁掉一角。

### 3.3 建议的坐标参考（造型不同可调整）

以"一只圆乎乎的小生物"为例：

```
        (256, 128)  ← 头顶（留白后从这里开始）
             │
     ┌───────┴───────┐
     │   ╭───────╮   │  ← 头部区域：y = 150 ~ 300
     │   │       │   │
     │  ◉     ◉     │  ← 眼睛中心建议 y ≈ 235
     │   ╰──┬──╯     │
     │      │        │  ← 嘴部建议 y ≈ 275
     │  ╭───┴───╮    │  ← 身体区域：y = 290 ~ 420
     │  │       │    │
     │  ╰───────╯    │
     │         ╲     │  ← 尾巴根部锚点建议 (340, 390)
     └───────────────┘
        (256, 440)  ← 脚底
```

**⚠️ 这些只是建议值，不是强制**。真正的强制要求是下面两条：

| 强制 | 说明 |
|---|---|
| **所有部件用同一张 512×512 画布** | 不要各自裁剪 |
| **中心对齐** | 各部件叠回去要严丝合缝 |

### 3.4 尾巴的旋转锚点（关键）

尾巴要能单独摆动，所以需要一个**旋转原点**。

**在交付时请说明**：尾巴图上，"连接身体的那一端"在画布上的坐标是多少（例如 `(340, 390)`）。

这个值前端会用来设 `transform-origin`。**如果不说，前端只能猜，摆起来就会脱节。**

## 4. 画面清单

> 每一项都给了：**画什么** / **什么时候出现** / **出现多久** / **优先级**

### 4.1 🟢 必需（4 项，缺了功能不完整）

#### 4.1.1 待机 idle

| 项 | 内容 |
|---|---|
| **画什么** | 最普通的静态姿势。眼睛睁开，表情平静（不是笑、也不是面无表情，是"安然"） |
| **什么时候** | **默认状态**，占 90% 以上的时间 |
| **出现多久** | 一直 |
| **注意** | **这张图决定了用户对它的第一印象**，多花点时间 |

#### 4.1.2 被摸 pat

| 项 | 内容 |
|---|---|
| **画什么** | 被轻轻摸了一下头的反应。可以是：眼睛眯起来、身体微微下沉、耳朵动一下 |
| **什么时候** | 用户点击它 |
| **出现多久** | 约 1 秒，然后回到待机 |
| **注意** | **不要画成"兴奋/狂喜"** —— 它是个安静的角色，反应要克制 |

#### 4.1.3 说话 talk

| 项 | 内容 |
|---|---|
| **画什么** | 张嘴的版本。或者只是表情有细微变化（如果造型不适合有嘴） |
| **什么时候** | 冒出对话气泡时 |
| **出现多久** | 气泡显示期间（3-5 秒） |
| **注意** | 如果造型没有嘴，可以改成"眼睛微微睁大"或"头上的光晕变亮" |

#### 4.1.4 睡觉 sleep

| 项 | 内容 |
|---|---|
| **画什么** | 闭眼 + 蜷缩/放松的姿势。可以有小小的"Zzz"（可选） |
| **什么时候** | 超过 10 分钟没有交互 |
| **出现多久** | 直到用户下次交互 |
| **注意** | **不要画成"累坏了"或"很可怜"** —— 是"安静地打盹"，不是"等得很辛苦" |

### 4.2 🟡 推荐（2 项，明显提升表现力）

#### 4.2.1 眨眼（睁 / 闭 两帧）

| 项 | 内容 |
|---|---|
| **画什么** | 就**只有眼睛部分**的两张图。睁眼 = 和 idle 一样；闭眼 = 一条弧线或一条线 |
| **什么时候** | 每 **4-8 秒随机**眨一次 |
| **出现多久** | **120 毫秒**（眨眼要快，慢了像睡着） |
| **⚠️ 关键** | **这两张图可以只画眼睛区域，其余部分透明** —— 前端会把它叠加在身体上 |

#### 4.2.2 初次见面

| 项 | 内容 |
|---|---|
| **画什么** | 歪头 / 探出头 / 刚醒来的样子 |
| **什么时候** | **领养的那一瞬间**，只出现一次 |
| **出现多久** | 3-5 秒 |

### 4.3 🔵 可选（有余力再做）

| 状态 | 什么时候 | 时长 |
|---|---|---|
| **开心** | 好感度升级时 | 2 秒 |
| **倾听** | 用户正在跟它说话（文字输入中） | 持续 |
| **安静等待** | AI 正在生成回复 | 持续（**注意：是"安静等待"，不是"着急"**） |
| **伸展** | 从睡觉状态被唤醒 | 1.5 秒 |

### 4.4 ❌ 明确**不要画**的（红线）

> **这一节是产品要求，不是美术建议。**
> 画得越可爱，用户越容易内疚 —— 所以下面这些东西**一张都不要画**。

| 不要画 | 为什么 |
|---|---|
| **难过 / 哭泣 / 眼眶湿** | 用户情绪不好时它不能显得难过，否则用户会想"是我让它不开心的"。**陪伴类产品最致命的错误** |
| **生气 / 皱眉 / 抱怨** | 情感勒索 |
| **生病 / 虚弱 / 躺倒 / 打补丁** | 会被理解成"因为我没来，所以它变差了" |
| **饥饿 / 肚子叫 / 脏兮兮** | 这是养成游戏的语言 |
| **睡觉时流泪 / 做噩梦** | 同上 |
| **催促的动作**（看表、来回走、扒门） | 同上 |
| **"可怜巴巴"的大眼睛** | 这是**乞求**的表情，会制造负罪感 |

**判断标准**：如果这张图让人产生"**我得赶紧去看看它**"的冲动 —— **画错了**。
我们要的是"**它一直在那儿，我什么时候去都行**"。

## 5. 图层拆分（**这一章最重要**）

### 5.1 为什么必须拆

显示尺寸只有 64-96px，但需要表现出：
呼吸、眨眼、摇尾巴、被摸反应、说话、睡觉……

**如果每个状态都画一整张全身图**：
- 画师要画 **6-8 张全身图**（工作量大）
- 前端要下载 **6-8 张 512×512**（体积大）
- 状态之间**切换会生硬**（因为是整图替换）

**拆成部件之后**：
- 画师只需 **3-6 张部件图**
- 前端用 **CSS 组合出十几种表现**
- 状态切换**丝滑**（因为身体不换，只换眼睛）

### 5.2 图层清单

```
📦 512 × 512 画布（所有图层共用）

├─ ① body.png            身体（含头、四肢、所有静态部分）
├─ ② eyes-open.png       眼睛 · 睁
├─ ③ eyes-closed.png     眼睛 · 闭
├─ ④ mouth.png           嘴巴 / 口部（可选）
├─ ⑤ tail.png            尾巴（可选，但强烈推荐）
└─ ⑥ accessory.png       配件（可选：角、触角、光晕、飘带……）
```

### 5.3 每个图层的详细要求

#### ① `body.png` —— 身体

| 项 | 要求 |
|---|---|
| **画什么** | 除了眼睛、嘴、尾巴、配件之外的**所有部分**。头部、身体、四肢、身上花纹 |
| **眼睛位置** | **要留出空白**（眼睛是独立图层，会叠在上面） |
| **尾巴位置** | **要留出空白**（尾巴会叠在身体下面，见下） |
| **嘴部位置** | 如果要独立嘴巴，这里也要留空 |
| **层序** | **最底层** |
| **⚠️ 注意** | 眼睛留白处**不要画眼窝阴影** —— 闭眼图层可能盖不住 |

#### ② `eyes-open.png` —— 眼睛（睁）

| 项 | 要求 |
|---|---|
| **画什么** | **只有眼睛**，其余全部透明 |
| **是否包含眼白/高光** | 包含。整个眼睛的完整视觉 |
| **层序** | **在 body 之上** |
| **范围** | 建议**只画眼睛周围一小块区域**，不用整张画布都填满（省体积） |
| **⚠️ 注意** | **位置必须和 body 上的留白完全对齐** |

#### ③ `eyes-closed.png` —— 眼睛（闭）

| 项 | 要求 |
|---|---|
| **画什么** | 闭眼。通常是一条向下的弧线，或者两道小短线 |
| **和睁眼图的关系** | **画布完全一致**，只有眼睛内容不同 |
| **⚠️ 关键** | **这两张图必须像素级对齐**，切换时不能有位移 |

#### ④ `mouth.png` —— 嘴巴（可选）

| 项 | 要求 |
|---|---|
| **画什么** | 张嘴的版本（说话时用）。不画这张的话，说话时可以用"眼睛睁大"代替 |
| **层序** | body 之上、眼睛之下（或之上，看造型） |

#### ⑤ `tail.png` —— 尾巴（**强烈推荐**）

| 项 | 要求 |
|---|---|
| **画什么** | **只有尾巴**，从"连接身体的那一点"开始往外 |
| **层序** | **在 body 之下**（尾巴是从身体后面长出来的） |
| **⚠️ 必须说明** | **尾巴根部在画布上的坐标**（例如 `(340, 390)`）—— 前端要用它做旋转原点 |
| **⚠️ 不要再画连接处** | 尾巴图和身体的接口处**不要有描边或阴影**，否则叠起来会看到一条线 |

#### ⑥ `accessory.png` —— 配件（可选）

| 项 | 要求 |
|---|---|
| **画什么** | 造型特有的装饰：头顶的光晕、触角、飘带、耳环…… |
| **有什么用** | 可以单独做"发光/浮动"动画 |
| **层序** | 通常在最上层 |

### 5.4 组合示意

前端会这样叠（z-index 从低到高）：

```
z-0 :  tail.png          （尾巴在最后面）
z-1 :  body.png          （身体）
z-2 :  mouth.png         （嘴在脸上）
z-3 :  eyes-open.png     （眼睛，眨动时切换成 closed）
z-4 :  accessory.png     （配件在最前）
```

**所以绘制时请记住**：你画的每一张，都是"**单独一层贴上去**"的，不是"一幅完整的画切块"。

## 6. 技术规格

| 项 | 要求 | 说明 |
|---|---|---|
| **格式** | **PNG-24 透明**（首选）<br>或 **WebP 有损透明**（体积小 30%） | 不要 GIF、不要 JPEG（JPEG 不支持透明） |
| **画布** | **512 × 512**，全部图层一致 | 不要各自裁剪 |
| **多倍率** | 提供 `@1x(256)` / `@2x(512)` / `@3x(768)`<br>或者只给 768 源图由前端缩 | @2x 是基准 |
| **安全边** | 四周 **40px** | 见 3.2 |
| **单文件体积** | **每张 ≤ 80 KB**（PNG）<br>**≤ 50 KB**（WebP） | 超了说明细节太多或没用压缩 |
| **总体积** | **6 张总计 ≤ 300 KB** | |
| **颜色模式** | RGB，sRGB 色彩空间 | 不要 CMYK、不要 Adobe RGB |
| **半透明** | 允许（光晕、渐变、阴影都行） | |
| **边缘** | **不要 1px 毛边** | 见 11.1 |
| **描边** | 如果有，**外描边**要统一宽度 | |
| **阴影** | 建议**不要**在图上画投影 | 投影由前端用 CSS `box-shadow` 或 `filter: drop-shadow()` 加，更灵活 |
| **源文件** | **必须提供** `.psd` / `.ai` / `.fig` | 以后改色、加新造型都靠它 |
| **命名** | 见第 7 章 | |

### 6.1 导出前的自检

```
□ 画布确实是 512×512（不是 500×512 或 513×512）
□ 背景是透明的（不是白色）
□ 图层位置没有偏移（叠起来检查）
□ 缩到 80px 看还能认出是什么
□ 文件体积没有超标
□ 边缘没有白边/黑边
□ 提供了源文件
```

## 8. 动画参数

> 这是前端会怎么动这些图。**画师看了这一章，就知道图的哪些部分会动**，从而避免画出"动不了"的图。

### 8.1 呼吸（一直播放）

```css
@keyframes pet-breathe {
  0%, 100% { transform: scale(1); }
  50%      { transform: scale(1.03); }
}
/* animation: pet-breathe 3s ease-in-out infinite; */

/* ⚠️ 缩放原点设在底部中心，看起来像"呼吸"而不是"放大" */
/* transform-origin: 50% 85%; */
```

**对图的要求**：底部要留一点余量，不然放大 3% 时脚会被裁。

### 8.2 漂浮（一直播放，和呼吸叠加）

```css
@keyframes pet-float {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-3px); }
}
/* animation: pet-float 4s ease-in-out infinite; */
```

### 8.3 眨眼（随机触发）

```
时间：每 4-8 秒随机一次
时长：120ms
实现：eyes-open.png ↔ eyes-closed.png 切换（不是 CSS 动画）
```

**对图的要求**：两张眼睛图**必须像素级对齐**。

### 8.4 摇尾巴（被摸 / 开心时）

```css
@keyframes pet-tail {
  0%, 100% { transform: rotate(-8deg); }
  50%      { transform: rotate(8deg); }
}
/* animation: pet-tail 0.6s ease-in-out infinite; */

/* ⚠️ 旋转原点 = 尾巴根部（由 README.txt 里的坐标换算而来） */
/* transform-origin: 66% 76%;   ← 例如 (340,390) / 512 = (66%, 76%) */
```

**对图的要求**：**必须告诉前端尾巴根部的坐标**，否则转起来会脱节。

### 8.5 被摸（点击时）

```css
@keyframes pet-pat {
  0%   { transform: translateY(0) rotate(0deg); }
  30%  { transform: translateY(-6px) rotate(-3deg); }
  60%  { transform: translateY(0) rotate(2deg); }
  100% { transform: translateY(0) rotate(0deg); }
}
/* animation: pet-pat 0.3s ease-out; */
```

### 8.6 睡觉（长时间无交互）

```css
/* 身体缩小一点点，并放在底部 */
.pet-sleeping {
  transform: scale(0.95) translateY(2px);
  transition: transform 0.6s ease;
}
/* 同时把眼睛切成 eyes-closed.png */
```

**对图的要求**：`tail.png` 如果要收起来，需要一个"收起的尾巴"版本，或者干脆用 CSS 把它旋转到贴着身体。

### 8.7 出现（领养 / 首次渲染）

```css
@keyframes pet-appear {
  0%   { opacity: 0; transform: scale(0.8) translateY(10px); }
  100% { opacity: 1; transform: scale(1) translateY(0); }
}
/* animation: pet-appear 0.4s cubic-bezier(0.34, 1.56, 0.64, 1); */
/* 那个 cubic-bezier 是弹性曲线，结尾会轻微过冲，感觉更可爱 */
```

### 8.8 动画叠加说明

**同时播放的动画**（比如呼吸 + 漂浮）需要包在不同的 DOM 层里，否则 `transform` 会互相覆盖。

前端结构会是：

```html
<div class="float">        <!-- 漂浮 -->
  <div class="breathe">    <!-- 呼吸 -->
    <img class="tail">     <!-- 摇尾巴 -->
    <img class="body">
    <img class="mouth">
    <img class="eyes">
    <img class="accessory">
  </div>
</div>
```

**画师不需要理解这个**，但要知道：**这几张图会被独立地动**。

## 11. 常见不合格示例

### 11.1 「边缘白边」

**现象**：图放到深色背景上，边缘有一圈淡淡的白色。

**原因**：在白色背景上画的，导出时没清干净，或者用了"消除锯齿"但没设置透明背景。

**怎么改**：导出时确认背景层已经关闭；PNG 导出选项里选"透明"；必要时用"修边/去边"功能。

### 11.2 「图层错位」

**现象**：眼睛叠上去，比身体上的留白高了几像素。

**原因**：每个图层单独裁剪后再导出，尺寸不一样了。

**怎么改**：**所有图层都保持在同一个 512×512 画布上导出**，不要裁。

### 11.3 「眼睛图层盖不住」

**现象**：眨眼时，透过闭眼的线还能看到身体上的眼窝。

**原因**：body.png 上画了眼窝阴影，而 eyes-closed.png 没覆盖那么大范围。

**怎么改**：**body 上眼睛的位置留纯空白**，所有眼睛相关的视觉都放在眼睛图层里。

### 11.4 「尾巴转起来脱节」

**现象**：摇尾巴时，尾巴和身体之间出现缝隙，或者尾巴从身体中间穿出来。

**原因**：旋转原点设错了 —— 前端只能猜，猜的位置不是尾巴根部。

**怎么改**：**在 README.txt 里写清尾巴根部坐标**。

### 11.5 「缩小后糊成一团」

**现象**：512px 看着很好看，缩到 80px 就是个色块。

**原因**：细节太多、对比度太低。

**怎么改**：减少细节，**增大剪影的辨识度**，提高主体和背景（这里是透明）的明度差。

### 11.6 「体积超标」

**现象**：一张 body.png 有 400KB。

**原因**：用了过多渐变、噪点、半透明图层，或者没开压缩。

**怎么改**：
- PNG 用 `pngquant` / TinyPNG 压缩
- 或者改用 WebP（同样画质体积小 30%）
- 减少不必要的渐变和噪点

### 11.7 ⚠️「画了难过的表情」

**现象**：一张"眼眶含泪""低着头很失落"的图。

**这不是技术问题，是产品问题。** 见 4.4 节。

**为什么不能要**：用户在情绪低落时看到它难过，会产生"**是我害的**"这种想法。陪伴类产品**最忌讳**这个。

**要什么**：用户在情绪低落时，它应该**保持它本来的样子，安静地在那儿**。

## 13. 三档交付方案

### 🥉 最小可行（3 张）


### 🥈 标准（5 张）

```
再加：
pet-{种类}-eyes-open.png       睁眼（独立图层）
pet-{种类}-mouth.png           说话张嘴
```

**效果**：加上说话的口型变化。

### 🥇 完整（6-8 张）

```
再加：
pet-{种类}-accessory.png       配件（光晕/触角）
pet-{种类}-sleep.png           睡觉专用姿势
```

**效果**：全部状态都有专门的画面。

**建议**：**先做 🥉 那三张，跑起来看看效果**，再决定要不要往下加。
因为**呼吸、眨眼、摇尾巴这三个动起来之后，已经能营造出"活着"的感觉了** —— 剩下的都是锦上添花。

## 14. 和代码的对接方式

> 这一章给前端看。

### 14.1 目录结构

```
public/pet/{种类}/
  pet-{种类}-body@1x.png / @2x.png / @3x.png
  pet-{种类}-eyes-open@2x.png
  pet-{种类}-eyes-closed@2x.png
  pet-{种类}-mouth@2x.png
  pet-{种类}-tail@2x.png
  pet-{种类}-accessory@2x.png
  pet-{种类}.json      ← 前端可读的元数据（由 README.txt 转换而来）
```

### 14.2 元数据格式（建议）

```json
{
  "species": "cat",
  "canvas": 512,
  "tailOrigin": { "x": 340, "y": 390 },
  "eyeCenter": { "left": { "x": 215, "y": 235 }, "right": { "x": 297, "y": 235 } },
  "colors": {
    "body": "#E8D5C4",
    "shadow": "#D0B8A3",
    "eye": "#4A3F35",
    "blush": "#F0C4C4"
  },
  "layers": ["tail", "body", "mouth", "eyes-open", "accessory"]
}
```

### 14.3 渲染结构

```jsx
// ⚠️ 动画叠加必须包在不同层里，否则 transform 会互相覆盖
<div className="pet-float">
  <div className="pet-breathe">
    <img src={withDensity("tail", 2)} className="pet-tail" alt="" />
    <img src={withDensity("body", 2)} alt="" />
    {speaking ? <img src={withDensity("mouth", 2)} alt="" /> : null}
    <img
      src={withDensity(eyesClosed ? "eyes-closed" : "eyes-open", 2)}
      alt=""
    />
    <img src={withDensity("accessory", 2)} alt="" />
  </div>
</div>
```

### 14.4 `transform-origin` 换算

```js
// README 里给的是 512 画布上的像素坐标，CSS 需要百分比
const origin = meta.tailOrigin;
const originCss = `${(origin.x / meta.canvas) * 100}% ${(origin.y / meta.canvas) * 100}%`;
// => "66.4% 76.2%"
```

### 14.5 倍率选择

```js
/**
 * 按屏幕像素密度选图。
 * ⚠️ 只提供 2x 也行 —— 前端缩放到 64-96px 显示，2x（512px）已经很清晰了。
 */
function withDensity(name, density = 2) {
  return `/pet/${species}/pet-${species}-${name}@${density}x.png`;
}
```

### 14.6 性能注意

- **`<img>` 要加 `draggable={false}`**（否则拖桌宠时会拖出图片幽灵）
- **首屏不需要预加载**（`PetWidget` 本身就是 `dynamic(ssr:false)`）
- **但可以在进站后 2 秒开始预加载图片**（等首屏渲染完），这样展开时不会闪
- **不要用 `<Image>` 组件**（Next 的 Image 会做额外的优化和请求，这几个小图没必要）
