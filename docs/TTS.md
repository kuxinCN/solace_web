# 语音朗读标签（TTS 情绪 / 声音事件）

> **一句话**：让 AI 在回复里自然带上 `[温柔]`、`(叹气)` 这类标签交给小米 MiMo 控语气，
> 但**用户看到的文字里这些标签会被剥掉**。
>
> 只跟一个接口类型有关：**小米 MiMo**（官方文档「风格控制 → 音频标签控制」）。
> 换成 OpenAI 兼容协议时整套逻辑自动失效，不会留下痕迹。
>
> 涉及文件：`lib/tts-tags.js`（**唯一的规则实现**）、`app/api/chat/route.js`（生成侧）、
> `app/api/tts/route.js`（发上游前按接口类型处理）、`app/api/tts/config/route.js`（前端拿配置）、
> `app/chat/page.js`（展示侧剥离）、`app/admin/page.js`（后台三个字段）。

---

## 一、链路：三段式，缺一段就出问题

```
① 生成   /api/chat 在 systemBlock 里拼一段「朗读标签」指令（仅 MiMo + 开关打开）
          ↓
② 存库   消息 content 保留**带标签的原文**（TTS 要靠它控语气）
          ↓
③ 展示   /chat 渲染前调 stripTtsTags → 屏幕上只有纯文本
          ↓
④ 朗读   前端把**带标签原文**发给 /api/tts
          ↓
⑤ 上游   MiMo 原样收下（认识标签）；OpenAI 兼容 → 服务端先剥掉再发（否则会被一字一顿念出来）
```

四个必须记住的位置：

| 位置 | 规则 | 为什么 |
|---|---|---|
| 生成侧 | 指令**请求时拼接**，绝不写进后台的人格提示词 | 人格提示词存在库里、所有部署共用一份；写进去会让"OpenAI 兼容 TTS"的部署也吐标签 |
| 展示侧 | 只剥 `assistant` 的消息 | **用户自己打的括号是内容**，不是标签 |
| 历史回喂 | 回喂前也剥（`stripTagsFromMessages`） | 模型看到自己上一轮的 `[温柔]` 会越贴越多 |
| 上游 | 按 provider 决定去留 | 库里的老消息可能来自 MiMo 时期，用户随时会切换接口类型 |

顺带也剥的两处（都是"AI 的回复喂给别的 AI / 展示给用户"）：对话**标题生成**、每日**记忆汇总**（`lib/daily-memory.js`）。

## 二、协议：代码只认什么

| 用途 | 官方写法 | 位置 | 括号 |
|---|---|---|---|
| 语气 / 风格 | `(温柔)`、`(开心 温柔)` | **整段最开头**（最多 1 个） | 半角 `()`；官方同时认全角 `（）` 与 `[]` |
| 声音事件 | `[叹气]`、`[紧张 深呼吸]` | 句中任意位置（最多 2 个） | 半角 `[]`；`［］`、`（）` 也认 |

- **生成侧按上面这套写**（`buildTtsTagInstruction`）；**剥离侧两种括号都认、也不看位置** ——
  历史消息里存的是 `[温柔]` `(叹气)` 那套旧写法，改了生成规矩之后照样要剥干净。
- 词与词之间：**逗号 / 顿号 / 空格**都行（官方："分隔符不限"）。
- `<叹气>` 只用于**兼容历史数据**。
- **故意不认 `【】` 与 `〈〉`**：那是中文正文里的强调与引用括号，误杀代价太高。
- ⚠️ **唱歌**：官方那节明确写「必须在最开头用 `(唱歌)`」，所以生成侧统一圆括号，别用 `[唱歌]`。

> **三种写法都实测过**（用 ASR 把合成结果读回来核对）：`(叹气)`、`（叹气）`、`[叹气]`
> MiMo 都能识别、都**不会**被念出来。所以"读出来"从来不是括号写错造成的 ——
> 真凶见下一节的**朗读侧净化**。

## 三、剥离：白名单闭合匹配（这是本功能最核心的决定）

```js
[ 开括号 ][ \t]* 词 ( 分隔符 词 ){0,3} [ \t]* [ 闭括号 ]
```

**只有"一对括号里正好是词表里的词"才算标签。** 所以：

| 文本 | 结果 | 说明 |
|---|---|---|
| `[开心]今天有点累` | → `今天有点累` | 正常剥 |
| `（叹气）我没事` | → `我没事` | 全角括号 |
| `（紧张，深呼吸）呼……` | → `呼……` | 多词、全角逗号 |
| `[sticker:comfort]` `[RISK:no]` `[MEMORY:xx]` | **不动** | 冒号 + ASCII，白名单天然不匹配 |
| `[1]` `[500]` `[链接](url)` | **不动** | 不是词表里的词 |
| `【重点】`〈引用〉 | **不动** | 全角方括号/书名号不在范围 |
| `（约 3 分钟）` `(int)` `(a+b)*c` | **不动** | 括号里不是词表里的词 |
| `我今天很开心` `笑了一下` `他叹了口气` | **不动** | 没有括号就永远不会被当成标签 |
| `[开心果]` `（开心起来）` | **不动** | 不是"完整的词" |

> 一句话原则：**漏 > 误杀**。漏了标签会在屏幕上显示出来（难看但没坏），
> 误杀了正常内容用户会看到缺字的回复。漏了就在后台词表里加个词。

两个额外处理：

1. **流式防闪**：文字一个字一个字到，`[开心]` 会先到 `[开`。流式渲染时传 `holdPartial`，
   尾部"开了口还没闭合"（≤20 字符）的半截标签先不显示；闭合后自动恢复。
   副作用：流式过程中正文里真的没写完的括号也会暂时不显示，流结束就正常。
2. **空白收拾**：剥离后折叠多余空格、清掉前后空行 —— 否则回复"以标签结尾"时，
   按 `\n` 切段渲染会凭空多出一个空气泡。

## 三·五、朗读侧净化（和展示侧剥离是两码事）

展示侧只做一件事：按白名单剥标签，原则是**漏 > 误杀**（漏了屏幕上多几个字，能忍）。
朗读侧不一样 —— **喂给 MiMo 的文本里只要混进"不是话"的东西，就会变成听感事故**，
所以要在 `/api/tts` 里再做两层净化（`lib/util.js` + `lib/tts-tags.js`）：

| 层 | 函数 | 去掉什么 | 不处理会怎样（**实测**） |
|---|---|---|---|
| ① | `stripEmoji`（`lib/util.js`） | emoji | `😊` 被念成"笑脸" |
| ② | `stripSymbolNoise`（`lib/util.js`） | 颜文字、ASCII 画、装饰线、网址 | `(￣▽￣)ノ 来一个` → 念成「**侬来一个**」 |
| ③ | `stripNonTagBrackets`（`lib/tts-tags.js`） | **白名单之外的括号内容**（人设的"括号动作描写"） | `(把手搭在你肩上)嗯，我在听呢。` → 念成「**把手搭在你肩上**，嗯，我在听呢」；<br>`（没说话，就坐在你旁边）嗯，那就难过一会儿吧` → **整句崩成乱码**「没做我调便宜呀，你想我可能设计彻底的吧？」 |

四条要点：

1. **第三条是这次的核心**：人设提示词里本来就写着"用括号写动作"，所以几乎每条回复都带
   `（动作描写）`。半角括号会被**念出来**，全角括号（尤其放在开头）会被 MiMo 当成
   **风格标签** —— 里面写的又不是风格，语气控制整个跑飞，整句合成变乱码。
2. **取舍是反过来的**：朗读侧用「**白名单之外一律去掉**」。代价是 `（约 3 分钟）`
   这种括号补充说明不会被念出来（用户在屏幕上照样看得到）——
   比起"听到乱码"，这个代价划算得多。
3. **顺序不能换**：先定标签去留（`(温柔)` 要留着控语气），再删非标签括号内容。
   反过来会把该留的语气标签一起删掉，等于这次朗读没有语气。
   实现上标签先被 `\u0001` 占位符保护，处理完再还原。
4. **最后一道防线在流式切句那一侧**：朗读是**逐句切、逐句合成**的，而切句只看标点 ——
   多词标签自带逗号（官方写法 `[紧张，深呼吸]`），**正好落在"逗号处切"的刀口上**。
   切出半截标签 `[温柔我好累啊…` 的后果是**整句崩成乱码**
   （实测听成「不可一定要提了，打上些观点，案外手是他…」）。所以：
   - `app/chat/page.js` 的 `drainSentences` 用 `hasOpenBracketTail()` 兜底：
     断在括号里的那句连同后面的句子一起退回待切文本，等标签闭合再切（宁可不切，不切半截）；
   - 文本流结束时（`flush`）用 `dropOpenBracketTail()` 把没闭合的那截丢掉，避免最后一句变乱码。
   这两处都是"少念一句"换"不念乱码"，和朗读侧其它取舍一个道理。

## 四、开关与词表（后台「语音 TTS」页）

> ⚠️ **别往词表里加英文词**：给模型看的词表只取**中文词**
> （`buildTtsTagInstruction` 里用 `/^[\u4e00-\u9fa5]+$/` 过滤，全英文的配置会原样保留兜底）。
> 原因是实测出来的 —— 模型对英文词特别敏感，会直接吐 `sing` 而且**容易忘掉括号**：
> 光秃秃一个 `sing` 会被念出来（听成「信，我好累啊…」），少个右括号的 `[sing`
> 更会把整句合成变成乱码（听成「缝好了呀，今天真的一点力气都没有」）。
> 官方文档里的英文等效值（`sing` / `singing`）留在**出厂词表**里做剥离兜底就够了。

| 字段 | 默认 | 作用 |
|---|---|---|
| **朗读标签**（开关） | **开** | 关掉 = 不生成也不剥（历史标签也会重新显示出来，慎用） |
| **语气标签词表** | 官方推荐表 50 个（48 + `sing`/`singing`） | ① 提示词告诉 AI 只能从这里选；② 用户端剥离白名单 |
| **声音事件词表** | 官方推荐表 30 个 | 同上 |

**生效条件（三个都要满足）**：`tts.enabled` + `tts.styleTags !== false` + `provider` 含 `mimo`。

| 场景 | 生成标签 | 用户端剥离 | 发上游前剥离 |
|---|---|---|---|
| MiMo + 开关开 + TTS 启用 | ✅ | ✅ | ❌（要留着控语气） |
| MiMo + 开关开 + **TTS 关闭** | ❌ | ✅（**必须继续剥**） | ❌ |
| MiMo + 开关关 | ❌ | ❌ | ❌ |
| OpenAI 兼容（含 `enabled` 任意） | ❌ | ❌ | ✅ |

> ⚠️ 第二行是刻意这样设计的：TTS 关掉后如果不再剥，历史消息里的 `[开心]` 会立刻在屏幕上现形。
> 所以"要不要剥"与"要不要生成"用了**两个不同的判定函数**（`isStyleTagsEnabled` / `shouldInjectTagInstruction`）。

> ⚠️ **清空词表 = 恢复默认**，不是"关掉功能"。想关功能请用开关。

## 五、五个坑（都踩过）

| 坑 | 说明 |
|---|---|
| **官方推荐表 ≠ 官方样例用词** | 官方样例里出现过 `苦笑`、`沉默片刻`、`小声`，这些**不在**推荐表里。默认词表收的是推荐表，所以这类词会漏到屏幕上（提示词里已禁止造词）。想支持就往词表里加 —— **不用改代码** |
| **提示词里给词表 = 一次红线边缘操作** | 项目红线「提示词里不给具体情绪示例」（模型会硬贴）。这里给的是一份**输出用词表**，已经加了两句约束："标签只表示这句话该怎么念，不是对用户情绪的评判""不确定就不贴"。若观察到**每条都硬贴**，把后台词表缩成子集即可（缩表后模型拿不到那些词，剥离白名单同步缩小也仍然自洽） |
| **`（笑）` 这类词会剥** | 「笑」在官方事件表里。它同时也是中文里的普通语气词 —— 本项目是情绪陪伴场景，判断为"会剥"更划算；不接受就从词表里删掉 |
| **标签跨 chunk** | 流式 holdback 掩盖；顺带把"正文里没写完的括号"也暂时挡住（一瞬间） |
| **词表被清空 / 配置读不到** | 词表空 → 回落出厂值；配置读不到 → 前端不剥 + 服务端不注入（两边自洽，等于没上这功能） |

## 六、验收清单

1. 后台「语音 TTS」能看到**朗读标签**开关 + 两个词表，且词表里是官方那两张表；
2. 接口类型不是 MiMo 时：AI 回复里**不应该**出现任何标签（`/api/chat` 不注入）；
3. 接口类型是 MiMo 时连发 3 条：气泡里**看不到** `[温柔]`/`(叹气)`；
4. 同一时刻去数据库看这条消息的 `content`：**标签还在**；
5. 点朗读：能听出语气/停顿跟着标签变了（对比"关掉朗读标签"前后）；
6. 把接口类型换成 OpenAI 兼容，朗读**同一条历史消息**：不能把"[开心]"念出来；
7. 用户消息里手打 `[开心]`：必须原样显示（不能被剥）；
8. 流式过程中不出现半截 `[开`；
9. 后台把词表加一个 `苦笑` → 回复里的 `(苦笑)` 立刻不再显示在气泡里。

### 自测：不靠耳朵，用 ASR 把合成结果"听写"回来

MiMo 自己有语音识别（`mimo-v2.5-asr`），所以"有没有被念出来"可以**自动验证**，
不用一遍遍听音频：

1. 用 `mimo-v2.5-tts` 合成待测文本（`messages: [{ role: "assistant", content: 文本 }]`，`audio.voice` 选音色）；
2. 把返回的 `choices[0].message.audio.data`（base64）丢给 `mimo-v2.5-asr`：
   `input_audio.data = "data:audio/mpeg;base64,…"`；
3. 看**转写里有没有出现标签或动作描写的文字** —— 出现就是被念出来了。

这次就是靠它定案的：10 组格式对照（`(叹气)`/`（叹气）`/`[叹气]`/`(温柔)`/`[温柔]`/`(唱歌)`/`[sing]`/
动作描写/颜文字）加 6 条真实消息。⚠️ 两个坑：

- 别把 ASR 的**误听**当成 bug：`token管够` 会被听成「偷看管够」——
  那是英文词识别错了，不代表 TTS 念错；判断"标签被念出来"只看**标签里的中文词有没有出现在转写里**；
- 语气有没有生效不看文字（标签本来就不会被念），要看**音频时长与节奏**：
  同一句话带 `(温柔)` 与带 `(愤怒)` 合成，时长/停顿会明显不同。

**已经实测过的样本**（照着复现，省得再试一遍）：

| 送进 TTS 的文本 | ASR 转写回来 | 含义 |
|---|---|---|
| `( º _ ºノ)` | **Sink.** | 颜文字被念成英文似的怪音 —— 用户报的"sink"就是它 |
| `(叹气)我没事` / `[叹气]我没事` / `（叹气）我没事` | 我没事 | 三种括号写法都安全，都会**被吞掉** |
| `(sing)…` / `[sing]…` / `(唱歌)…` | 我好累呀… | 带括号的英文标签也安全 |
| `sing我好累啊` | **信**，我好累啊 | 裸写的英文**会被念出来** → 词表别给模型看英文 |
| `[sing我好累啊…`（少个右括号） | 缝好了呀，今天… | 半截标签 → **同一句被念成别的话** |
| `[温柔我好累啊…`（少个右括号） | 不可一定要提了，打上些观点… | 半截标签 → **整句变乱码** |
| `I need to check the system instructions. 我好累啊` | 1. I need to check… | 英文思考串味会被**完整念出来** |
| `(￣▽￣)ノ 来一个` | 侬来一个 | 颜文字被拼读 |
| `(把手搭在你肩上)嗯，我在听呢。` | 把手搭在你肩上，嗯，我在听呢。 | 半角动作描写被念出来 |
| `（没说话，就坐在你旁边）嗯，那就难过一会儿吧` | 没做我调便宜呀，你想我可能设计彻底的吧？ | 全角动作描写（开头）→ **整句变乱码** |

> ⚠️ **第 3 条不通过（气泡里还能看到标签）时，按这个顺序查 —— 别先去动剥离逻辑**：
>
> 1. **配置**：后台「接口类型」是否含 `mimo`、**朗读标签**开关是否开着。
>    不是 MiMo 就**本来就不该剥** —— 这种情况属于配置问题，不是 bug；
> 2. **浏览器拿到的是哪份 JS**：无痕窗口 / `Ctrl+F5` 再看一次首页聊天。
>    部署前打开着的标签页会一直演旧行为；控制台里可以自证：
>    ```js
>    performance.getEntriesByType('resource')
>      .filter(r => /chunks\/app\/chat\/page-/.test(r.name)).map(r => r.name.split('/').pop())
>    ```
>    再对比线上 HTML 里引用的那一份：
>    `curl -s http://127.0.0.1:3000/chat | grep -o 'chunks/app/chat/page-[^"]*\.js'`；
> 3. **构建是不是真的成功了**：看 `npm run build` 的**退出码**是否为 0。
>    ⚠️ 只看 `✓ Compiled successfully` 会被骗 —— 它在 lint **之前**就打印，
>    lint 报 Error 时构建照样以退出码 1 结束，`.next` 停在半更新状态：
>    **新接口能请求到、用户端 JS 还是旧的**（详见 [INCIDENTS.md](./INCIDENTS.md) INC-016）。
>    把线上那份 `page-*.js` 下下来搜 `includes("mimo")` 与 `holdPartial` ——
>    两处调用点都在，就说明剥离逻辑已经在线上包里了，问题不在它身上。

## 七、改动入口速查

| 想改什么 | 改哪里 |
|---|---|
| 换 / 加词 | 后台「语气标签词表」「声音事件词表」（**不用改代码**） |
| 整个功能关掉 | 后台「朗读标签」开关 |
