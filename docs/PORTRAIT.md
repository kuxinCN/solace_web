# 用户心理画像

> 这份文件对应任务里说的「心理画像方案」。**判定规则全部本地执行，不调用任何 AI。**
>
> 实现代码：`lib/portrait.js`（算法）· `lib/scales.js`（题库）
> 相关文档：[STRESS-DESIGN.md](./STRESS-DESIGN.md)（压力评估）· [API.md](./API.md)（接口）

## 一、为什么要做成本地规则引擎

三个理由，写下来是为了以后别被"换成 AI 判定是不是更准"这种想法带跑偏：

| 理由 | 说明 |
|---|---|
| **可复现** | 同样的输入永远得到同样的画像。用 AI 判定的话，同一个用户今天算"高"、明天可能算"中"，而它会影响**每一次聊天的语气** —— 这种不稳定是不可接受的 |
| **可解释** | 每个标签都能追溯到"哪个分数、用了哪条规则"。后台会把**原始分数和标签一起显示**，运营不会只看标签猜依据 |
| **可版本迭代** | 算法改了就把版本号加一。老用户不会被动重算（等下次触发条件满足时再按新规则算），"这个标签是哪版算法给的"始终说得清 |

> ⚠️ 还有一个现实考虑：画像会影响**每一次** AI 回复的 system prompt。
> 如果判定要走一次大模型调用，那就是"每条消息前先多花一次钱"，而且引入了不确定性。

## 二、五个维度

| 维度 | 取值 | 数据来源 |
|---|---|---|
| **年龄段** | 青少年 / 青年 / 成年 / 中年 / 老年 | 用户资料里的**生日**推算 |
| **压力水平** | 低 / 中 / 高 | PSS-10 + 自研压力值 |
| **情绪风险** | 低 / 中 / 高 | GAD-7 + PHQ-9 |
| **人格倾向** | 内向 / 外向 | MBTI 的第 1 位（E/I） |
| **沟通偏好** | 直接 / 温和 | MBTI 的第 3 位（T/F） |

MBTI 的 S/N 和 J/P 两位**不参与**风格指令生成，但保留在画像 JSON 里供后台参考。

### 为什么「年龄段」排在第一

`PORTRAIT_KEYS` 的顺序**就是指令的拼进 system prompt 的顺序**，年龄段排最前是因为它的优先级最高：

> 年龄段为「青少年」时，其指令**优先于**其他维度的风格要求。
> 涉及自伤、抑郁等敏感话题时，必须引导用户向信任的成年人或专业机构求助，
> **可以覆盖**其他维度中可能过于成人化的表达。

**判定**（纯本地，不调 AI）：

| 年龄 | 年龄段 |
|---|---|
| < 18 | 青少年 |
| 18–25 | 青年 |
| 26–40 | 成年 |
| 41–60 | 中年 |
| > 60 | 老年 |

**边界情况**：

- **没填生日** → 跳过年龄段，不影响其他维度（画像里是空字符串）
- **年龄异常（< 10 或 > 100）** → **照样给标签**（按最近的档），但标 `ageNeedsReview`，后台显示"建议核实生日"。
  ⚠️ 不给空标签是有意的 —— 空标签等于这类用户**完全拿不到**年龄指令。
- ⚠️ **画像里只存年龄段，不存具体年龄值** —— 年龄一直在 `users.birthday` 里，
  这里只留下"需要什么说话方式"这个结论。

## 三、判定规则

### 维度一：压力水平

```
PSS_norm    = PSS分数 / 40
Stress_norm = 聊天压力值 / 100
combined    = PSS_norm × 0.6 + Stress_norm × 0.4

combined < 0.35 → 低
combined < 0.65 → 中
否则           → 高
```

**权重 0.6 / 0.4 是有意的**：量表是标准工具、用户认真填的，更可信；
聊天压力值连续采样、反应快但噪声大。让**量表主导、压力值做修正**。

**阈值为什么是 0.35 / 0.65**：PSS-10 常以总分 ≥20 作为"高压力"分界（约 50% 分位以上），
归一化是 `20/40 = 0.5`。这里把高压线定在 **0.65**，是**再往上抬了一档** ——
因为"高压力"会换来更克制的回复风格（更简短、少追问），**宁可少标、不要错标**。

**缺 PSS 时**：只用聊天压力值（新用户还没做测评也得给个判断，这是方案里的回退分支，不是降级）。

### 维度二：情绪风险

```
GAD_norm = GAD分数 / 21
PHQ_norm = PHQ分数 / 27
combined = GAD_norm × 0.5 + PHQ_norm × 0.5

combined < 0.2  → 低     （约 GAD 4 分以内 / PHQ 5 分以内）
combined < 0.45 → 中     （约 GAD 9 分 / PHQ 12 分）
否则            → 高
```

**⚠️ PHQ-9 第 9 题（自伤念头）单独处理：**

> **只要有分，情绪风险直接判「高」**，并在画像里带一个 `needsAttention` 标记，
> 后台会显示"需关注"。

这一条**不看总分、不做加权、不参与平均**。自伤念头的存在本身就是需要关注的信号，
被平均分稀释掉是不可接受的 —— 一个 PHQ 总分只有 6 分、但第 9 题答了 1 分的人，
不应该因为"总分不高"而被判成低风险。

### 维度三 / 四：人格倾向与沟通偏好

```
MBTI 第 1 位 = I → 人格倾向 = 内向
MBTI 第 1 位 = E → 人格倾向 = 外向

MBTI 第 3 位 = T → 沟通偏好 = 直接
MBTI 第 3 位 = F → 沟通偏好 = 温和
```

**只取一位，不做"综合评估"** —— 画像要可解释。
"因为你是 INTJ 所以内向"这句话用户和运营都看得懂，
而"综合多个维度得出你偏内向"没人能验证。

## 四、标签 → 聊天风格指令

| 维度 | 取值 | 追加的指令 |
|---|---|---|
| 压力水平 | 高 | 用户压力较高：回复更简短，先共情再给建议，不要长篇大论。 |
| 压力水平 | 中 | 用户有一定压力：保持温和，适当给予支持。 |
| 情绪风险 | 高 | 用户情绪风险较高：避免说教和评判，多确认他的感受。 |
| 情绪风险 | 中 | 用户情绪偏低：注意语气柔和。 |
| 人格倾向 | 内向 | 用户偏内向：少追问，给他思考的空间，回复简洁。 |
| 人格倾向 | 外向 | 用户偏外向：可以适当互动，回复可以稍长一些。 |
| 沟通偏好 | 直接 | 用户偏好直接表达：减少铺垫，逻辑清晰。 |
| 沟通偏好 | 温和 | 用户偏好温和表达：注意措辞的友善和共情。 |

**拼接方式**：

```
最终 system prompt = 后台全局人格提示词 + "\n\n" + "当前用户适配（…）" + 指令列表
```

**写这些句子的两条原则**（改的时候请保留）：

1. **说"怎么回"，不说"用户是什么样的人"** ——
   写「用户是内向的人」，模型容易在回复里**体现出**"我在把你当内向的人对待"；
   写「少追问、给思考空间」，它会直接照做。
2. **每条都要能立刻执行** —— 「注意语气」这种话模型没法落地，「回复更简短」才能。

**⚠️ "低"是刻意没有对应指令的**：低压力 / 低情绪风险**不需要特别调整**。
给模型加一堆"用户状态很好"的指令，反而会让语气变得轻快 ——
对一个来倾诉的人是不合时宜的。

**回退逻辑**：某个维度缺数据 → **该条指令直接跳过**，只拼已有的。
一条都没有（新用户没做任何测评）→ 返回空字符串，**只用全局人格提示词**，不报错、不降级。

## 五、画像 JSON 结构

```json
{
  "portrait": {
    "压力水平": "高",
    "情绪风险": "中",
    "人格倾向": "内向",
    "沟通偏好": "直接"
  },
  "basis": {
    "压力水平": "PSS 24/40（权重 0.6） + 聊天压力值 78/100（权重 0.4）",
    "情绪风险": "GAD-7 12/21 + PHQ-9 8/27（等权）",
    "人格倾向": "MBTI INTJ 的第 1 位是 I",
    "沟通偏好": "MBTI INTJ 的第 3 位是 T"
  },
  "sourceScores": {
    "PSS": 24, "GAD": 12, "PHQ": 8,
    "PHQ9SelfHarm": 0, "chatStress": 78, "MBTI": "INTJ"
  },
  "needsAttention": false,
  "portraitVersion": "v1",
  "updatedAt": "2026-09-24T10:00:00.000Z"
}
```

> ⚠️ **`basis` 是方案之外额外加的**。原始方案只给了标签和分数，
> 但后台展示时"PSS 24 / 压力值 78"这种缩写，运营还是得自己推。
> 多存一份**判定依据的文字说明**，排查时能省很多事 —— 代价只是几十个字节。

**存储位置**：`users` 表的三列 —— `portrait`（JSON）、`portrait_version`、`portrait_updated_at`。
**用户端不可见**，只在后台「用户管理」「用户数据」展示。

## 六、触发更新

满足任意一条就重算全部维度：

1. 用户完成 **PSS-10 / GAD-7 / PHQ-9 / MBTI** 任一测评时
2. 自研压力值**单次变化超过 15** 时
3. 距离上次画像更新**超过 7 天**，且用户有新测评数据

> ⚠️ 第 3 条的"且用户有新测评数据"不能省 ——
> 否则每 7 天给一个从不测评的用户重算一次，画像内容一模一样，纯属白跑。

## 七、后台展示

```
心理画像（v1 · 2026-09-24 更新）
├─ 压力水平：高    ← PSS 24/40（权重 0.6） + 聊天压力值 78/100（权重 0.4）
├─ 情绪风险：中    ← GAD-7 12/21 + PHQ-9 8/27（等权）
├─ 人格倾向：内向  ← MBTI INTJ 的第 1 位是 I
└─ 沟通偏好：直接  ← MBTI INTJ 的第 3 位是 T
```

**原始分数和画像标签分开展示** —— 避免运营人员只看标签、不知依据。

## 八、边界情况

| 情况 | 处理 |
|---|---|
| 用户未做 MBTI | 跳过人格倾向和沟通偏好指令（标签留空） |
| 用户未做 PSS | 压力水平只用聊天压力值判定 |
| GAD / PHQ 只测了一个 | 只用测了的那个算 |
| **PHQ-9 第 9 题有分** | 情绪风险**强制判「高」** + 后台标记「需关注」 |
| 一条数据都没有 | 四个标签都留空 → 不追加任何指令，只用全局人格提示词 |
| 画像版本升级 | **老用户不自动重算**，等下次触发条件满足时用新规则算 |
| 题库被停用 | 已有测评结果不受影响（画像是快照，不回头改） |

## 九、和其它模块的关系

| 模块 | 关系 |
|---|---|
| **自研压力值**（`lib/stress-*.js`） | **只读**。画像读它的 `combined_score`，**不修改、不重训、不替换它的算法** |
| **压力评估的提醒弹窗** | 两条独立的链路：弹窗**不看画像**（它只看当时的分数），画像**不触发弹窗**（它只改聊天风格） |
| **后台「对话 AI」的全局人格提示词** | 画像指令是**追加**在它后面的，不替换、不覆盖。全局提示词始终生效 |
| **情绪标签 / 日记打标** | 无关联。那两套是"给内容打标"，这里是"给用户建模" |
